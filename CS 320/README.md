# CS 320 Software Testing, Automation, and Quality Assurance

How can I ensure that my code, program, or software is functional and secure?

One of the biggest things I took from this course is that code working does not always mean it works correctly. Testing made me realize how thorough you actually have to be. With the contact service, I tested normal inputs, boundary values, null values, duplicate IDs, and other invalid inputs. This helped catch problems that might not show up when only testing the expected situations. I think keeping validation in mind also helps make software more secure, because the program should control what information it accepts rather than assuming every input will be correct.

How do I interpret user needs and incorporate them into a program?

I think interpreting user needs starts with paying attention to the details in the requirements. Something that sounds simple, like limiting an ID to 10 characters, still has to be correctly implemented in the program and tested to ensure the limit actually works. This course helped me look more closely at requirements rather than just focusing on getting the main function of a program working. I also learned that testing in different situations can help show whether the program really meets the original requirements.

How do I approach designing software?

My approach is to keep the software organized while making it as efficient as possible. I do not think adding more code automatically makes a program better. Separating responsibilities between classes and keeping the code understandable makes it easier to work with and test. Going through these projects also changed how I look at testing during the design process. Instead of thinking of testing as something to do after everything is finished, I think it makes more sense to consider how different parts of the program will be tested as I build them.
